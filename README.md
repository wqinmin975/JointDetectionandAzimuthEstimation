# Joint Detection and Azimuth Estimation of Drones via MEMS Microphone Arrays and Multi-Task Deep Learning

Code and simulation release accompanying the manuscript submitted to **MDPI *Sensors***
("Joint Detection and Azimuth Estimation of UAVs Using MEMS Microphone Arrays and
Multi-Task Deep Learning: From Simulation to Real-World Recordings", manuscript
sensors-4688906). A point-by-point reply to the reviewers is in
`response_to_reviewers.md`.

> All experiments in the core pipeline are **pure numerical simulation** (no hardware
> measurements). This revision corrected several genuine defects in the original
> experiments; all numbers in the revised paper are regenerated by the code below. The
> real-data branch validates on the Fraunhofer IDMT `MicArrayData30s` recordings and the
> Western Sydney University (WSU) corpus.

## Which script produces the reported numbers

The revised manuscript's Table I, Fig. 2 and the paired benchmark come from the **V3**
protocol, which fixes the following defects found during revision: (i) negative samples
no longer enter the regression loss with an artificial 0° target (masked loss); (ii) the
training loss is now a 180°-periodic circular L1, matching evaluation; (iii) inter-mic
delays are fractional (zero-padded frequency-domain phase ramp) instead of rounded to
integer samples; (iv) properly trained single-task references (Solo-Det / Solo-Loc) were
added; and (v) the log-variance parameters of the dynamic weighting are now included in
the optimizer — in the earlier versions they were constructed after the optimizer and
never updated.

## How to reproduce

1. **Simulation — revised Table I and Fig. 2 (final protocol):**
   ```bash
   python drone_acoustic_joint_v3.py --mode simv3
   python baseline_snr_v3.py
   ```
   These write `table1_repro_v3.csv`, `data_snr_v3.csv`, the `*_v3.csv` ablation curves,
   and the paired-benchmark CSVs.

2. **Unpaired Welch test:** `welch_test.csv` reports the non-paired Welch comparison on
   the Table I classical-vs-network MAE values.

3. **Real-data evaluation** (requires Fraunhofer IDMT `MicArrayData30s`, Zenodo
   `10.5281/zenodo.17525811`, and the WSU corpus):
   ```bash
   python drone_acoustic_joint.py --mode real      # IDMT zero-shot + fine-tune
   python wsu_eval.py                              # WSU classical evaluation
   ```

4. **Compile the manuscript** on `paper_mdpi.tex` (or run the MDPI build chain from
   `Definitions/`).

## Reproducibility and honesty notes

- Every training configuration resets `np.random.seed(42)` + `torch.manual_seed(42)`;
  ablated variants share data and initialization. The fixed-weight variants were verified
  to be bit-identical between v2 and v3 (max difference 0.0).
- With all defects corrected, **dynamic uncertainty weighting did not improve peak
  azimuth accuracy over fixed equal weighting** (7.50° vs 5.62° at −5 dB), and properly
  trained single-task localization matched or slightly exceeded the joint model (5.95°).
  The paper reports these findings plainly; the value of dynamic weighting is stated as
  avoiding a manual weight search, not as higher accuracy.
- The detection task is saturated (Pd = 1.00, Pfa = 0.00 at all tested SNRs), so these
  simulations do not exercise partial-detection operating points.
- The IDMT result is an **in-sample** adaptation figure. The reported 18.05° is a
  180°-folded azimuth-axis error; unfolded to the full circle it is approximately
  78–103°. The task is therefore described as 180° azimuth-axis estimation, and the
  learned detector's real-world false-alarm rate remains unvalidated.
